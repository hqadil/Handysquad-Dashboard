# HANDY SQUAD COMPLAINT MANAGEMENT PLATFORM
## Master Engineering Deployment Specification & Architecture Manual

This document provides complete instructions for provisioning, configuring, securing, and deploying the Handy Squad Complaint Management & Operations Platform on Supabase and Next.js.

---

### 1. Architectural Overview & Technology Stack

The platform is engineered specifically for Handy Squad's home-services operations across Kerala (Kochi, Trivandrum, Kozhikode, Thrissur):

- **Frontend / Application Layer**: Next.js 13.5 (React 18 + TypeScript), Tailwind CSS, Radix UI.
- **Database**: Supabase PostgreSQL with 16 normalized relational tables, foreign key constraints, composite indexes, and strict CHECK constraints.
- **Security & Authorization**: Row Level Security (RLS) on 100% of exposed tables, denying all access by default with role-specific grant policies.
- **File Storage**: Supabase Storage with private bucket `complaint-evidence` delivering short-lived signed URLs (3600s expiration). Public access is completely blocked.
- **Timezone**: All timestamps are natively stored in UTC and presented to operations in `Asia/Kolkata` (IST).
- **Automated Test Suite**: Jest + ts-jest covering Responsibility Engine multi-party liability, Section 8 financial safeguards, and approval tier routing.

### 2. Database Schema & Migration Execution

All database changes are managed via version-controlled SQL migrations located in `supabase/migrations/`:

1. `20261017000001_complaint_management_schema.sql`: Core tables, sequences, triggers, and functions.
2. `20261017000002_complaint_management_rls.sql`: Row Level Security policies and role helpers.
3. `20261017000003_complaint_management_seed.sql`: Kerala hubs, staff roster, seed tickets, and governance rules.

#### Migration Application Methods:

**Option A: Using Supabase CLI (Recommended for CI/CD)**
```bash
# Authenticate and link Supabase project
npx supabase login
npx supabase link --project-ref <your-supabase-project-ref>

# Apply schema migrations to remote database
npx supabase db push
```

**Option B: Using Supabase SQL Web Editor**
1. Open your Supabase Dashboard -> **SQL Editor**.
2. Run `supabase/migrations/20261017000001_complaint_management_schema.sql`.
3. Run `supabase/migrations/20261017000002_complaint_management_rls.sql`.
4. Run `supabase/migrations/20261017000003_complaint_management_seed.sql`.

### 3. Private Supabase Storage Configuration

Per **Section 6 of the Master Engineering Specification**, customer photos, work orders, audio recordings, and checklists must never be stored in public buckets.

1. In Supabase Dashboard, navigate to **Storage** -> **Create a new bucket**.
2. Name the bucket: `complaint-evidence`.
3. Set **Public Bucket**: **OFF** (Toggle to Private).
4. Run the storage RLS policy in Supabase SQL Editor:

```sql
-- Allow authenticated staff to view evidence via signed URLs
CREATE POLICY "Allow authenticated staff to read evidence"
ON storage.objects FOR SELECT
TO authenticated
USING (bucket_id = 'complaint-evidence' AND (auth.role() = 'authenticated'));

-- Allow internal operations to upload evidence
CREATE POLICY "Allow operations staff to upload evidence"
ON storage.objects FOR INSERT
TO authenticated
WITH CHECK (bucket_id = 'complaint-evidence');
```

Signed URLs are dynamically generated by `/api/complaints/[id]/evidence` with a maximum TTL of 3,600 seconds (1 hour).

### 4. Server-Controlled Roles & Row Level Security

The application enforces 7 discrete role privileges:
- `BDA_SALES`: Can register complaints and view customer booking communication.
- `SCHEDULING_TEAM`: Can view appointments and assign technicians.
- `OPERATIONS_TEAM`: Field coordinators and investigators.
- `OPERATIONS_MANAGER`: Approves investigations and expenses $\le ₹5,000$.
- `COO`: Dual-authorizes major cases ($₹5,000 - ₹15,000$) and goodwill policies.
- `HR`: Audits employee training status, certifications, and coaching assignments.
- `MANAGEMENT_ADMIN`: Unrestricted executive audit and board-level sanction ($> ₹15,000$).

RLS is enabled on all tables:
```sql
ALTER TABLE public.complaints ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.complaint_participants ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.complaint_evidence ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.investigation_records ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.responsibility_assessments ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.cost_records ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.approval_records ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.corrective_actions ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.training_records ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.audit_log ENABLE ROW LEVEL SECURITY;
```

Before deploying to staging or production, execute the automated verification suite:


### 7. Backup, Disaster Recovery & Point-In-Time Restore

- **Automated Backups**: Supabase Pro projects automatically maintain daily backups with Point-In-Time Recovery (PITR) up to 7 days.
- **Manual Snapshots**:
  ```bash
  # Dump complete schema and table data
  pg_dump -h db.<PROJECT-REF>.supabase.co -U postgres -d postgres -F c -b -v -f "handy_squad_backup_$(date +%Y%m%d).dump"
  ```
- **Disaster Recovery RTO/RPO**:
  - Recovery Time Objective (RTO): $< 30$ minutes.
  - Recovery Point Objective (RPO): $< 5$ minutes (WAL archiving).
